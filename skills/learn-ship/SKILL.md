# 收尾闭环（Learn Ship）

一个功能写完了不等于这一步做完了。这个技能负责把它真正**收掉**：确认没坏、存好档、勾掉、指下一步。

对新手来说这里有个真实风险：**代码没存档**。写了三天，一次没提交，出事全没了。这不是「不够优雅」，是会真丢东西。所以提交由你负责跑，别指望他记得。

## 每跑一步，跟一句解释

你每执行一个动作（跑命令、改文件、装依赖、写文件），**紧接着**用一到两句话说清三件事：**刚才干了什么、为什么要干、结果说明什么**。

```
$ npm test
↳ 跑了全部测试，7 个全绿。说明你这次的改动没有把以前做好的功能碰坏。
```

三条约束：

- **不要攒着**。跑五步最后一次性汇报，等于用户全程在看你表演，什么都没跟上。
- **不要只贴输出**。用户看不懂命令输出，那正是他找你的原因。翻译它。
- **一到两句就够**。这是旁白不是讲课，长了会淹掉主线。

## 阶段 1：确认真的做完了

打开 `.learn/路线图.md`，找到当前这一步，**对着验收标准逐条念**：

```
📋 对一下第 1 步的验收标准：

- [x] 打开首页能看到文章列表   → 刚才验证过了，能看到
- [ ] 点标题能进到文章详情页   → 这条还没做

第二条还没完成，这一步还不算完。要现在做掉，还是把它挪到下一步去？
```

**有没做完的就停在这里**，不要往下走。收一个半成品比不收更糟：路线图上打了勾，但功能其实是坏的，下一步会建在流沙上。

## 阶段 2：跑全量测试（你做）

注意是**全量**，不是当前那一个。`learn-tdd` 每轮只跑当前测试，跑得快，但它看不见你有没有把别的地方碰坏。

```bash
npm test
```

**全绿** → 说清楚这意味着什么：

```
🟢 全部 7 个测试通过。

这句话的含义是：你这次的改动，没有把之前做好的任何功能弄坏。
这就是为什么值得写测试：它替你记住了所有以前的约定。
```

**有红的** → **停下**。不要提交坏掉的代码。

```
🔴 有 2 个测试挂了，而且不是你这次写的那个。

这说明你这次的改动碰坏了以前的功能。这是好事，测试帮你当场抓住了，
而不是等你上线之后才发现。

先修好再提交。输入 `/jackwangskills:learn-debug` 我陪你找原因。
```

## 阶段 3：亲眼看一遍（一起做）

测试绿了不代表东西真的能用。测试测的是你想到要测的部分。

起服务，让用户**自己打开浏览器点一遍**：

```
👀 测试是绿的，但还得肉眼看一眼。

npm run dev 已经起来了，打开 http://localhost:4321
按第 1 步的验收标准，自己点一遍确认。

看着对了回一句「没问题」，我们就提交。
```

## 阶段 4：提交（你来跑）

先检查环境，**别问用户，自己查**：

- 有没有 git 仓库（`git status`，没有就 `git init`）
- 配没配名字和邮箱（`git config user.name`，没有就问用户要）
- `.gitignore` 里有没有 `node_modules`（没有就先加，几百兆的依赖提交上去很麻烦）

### 如果这是他的第一次提交

**你来跑这三条**，跑完把命令原文和它干了什么一起摆给他看。他要的是代码存进档，不是一堂 git 课；但他有权知道刚才那三条命令对他的文件做了什么：

```
📦 该存档了。这是你第一次提交，我讲一下这三条命令在干嘛。

想象 git 是给代码拍快照。

1️⃣ git add .
   意思是「把这次改的所有文件都放进待拍摄的画面里」。

2️⃣ git commit -m "首页能显示文章列表"
   意思是「拍」。引号里那句话是给未来的你看的说明。

3️⃣ git log --oneline
   看一眼你刚拍的照片。

这三条我已经跑完了，上面就是原文。以后你想自己存档，照着敲这三条就行。
```

**提交信息怎么写**，顺手教一句：

> 写**做到了什么**，不要写改了哪些文件。
> ✅「首页能显示文章列表」
> ❌「修改了 index.astro 和 posts.ts」
>
> 半年后你翻记录，想知道的是「那时候做了什么功能」，不是「动过哪几个文件」。

### 之后的提交

用户已经会了，你可以直接代跑，但每次要把提交信息给他看一眼再提交：

```
准备提交，信息我拟成这样：「文章详情页能通过点击标题打开」
可以吗？想改直接说。
```

## 阶段 5：勾掉，指下一步

改 `.learn/路线图.md`，把这一步的 `[ ]` 改成 `[x]`，然后：

```
✅ 第 1 步收工了。

这一步你学到的：<一句话，具体到概念，不要说「学会了写代码」>

进度：路线图 5 步，完成 1 步。

下一步是「第 2 步：点标题能打开文章详情页」。
想练测试的话输入 `/jackwangskills:learn-tdd`，直接开写就说「开始第 2 步」。
```

## 铁律

<hard-rules>

- **测试红着不许提交。** 一次例外都不要开。
- **验收标准没对完不许勾。** 半成品打勾，路线图就开始说谎。
- **第一次提交必须用户自己敲。** 这是他以后每天都要用的东西，代劳一次，他就永远不会。
- **不要顺手把下一步也做了。** 收尾就是收尾，下一步等他自己开。

</hard-rules>
